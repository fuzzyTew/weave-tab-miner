      If this network blocks Arweave

      Try the source test below, another network, or a phone hotspot. Tor can also run inside a web page: tor-js and webtor-rs build it into WebAssembly and use Snowflake to get through blocks. This page does not include it yet (see TODO.md). On a shared or work network, ask before routing around its filter.

      Not finished yet

      • No block from a tab has yet been seen on the mainnet. A test network has taken a tab's block, with the tab's own accounts, packing, VDF steps and signature; its second block is under study.
      • Tabs sharing a key on different devices could both solve at one height; signing both would get the key banned. Rare; waits on tabs being able to talk to each other.
      • The first visit reads all accounts (about 300,000) from a node before it can publish, which takes minutes on a phone; later visits within a day catch up block by block.
      • The weave's oldest partitions (0–8) are held by their chunks' own ends, not yet seen in a mainnet block, so the page picks partitions from 9 on.

      The full list, with what is done, is docs/TODO.md. To continue with Claude, ask: “Continue weave-tab-miner (github.com/fuzzyTew/weave-tab-miner): pick the next task in docs/TODO.md, test it against real nodes, and commit each step separately.”

      Other ways to keep data permanently

      A page can only speak HTTP and a few browser protocols. Tor would let it reach any TCP port, and libp2p in the browser reaches networks such as Autonomi, so one client could compare and mirror across these. Not built yet (see TODO.md).

      • Arweave: pay once; miners are paid to keep replicas, and one surviving copy can restore the rest.
      • ArDrive Turbo: an Arweave bundler; items up to 100 KiB free, larger ones paid by card or crypto.
      • Autonomys (Auto Drive): pay once; farmers are paid to hold erasure-coded pieces of all history.
      • Autonomi (formerly MaidSafe): pay once at upload; nodes keep copies as they join and leave.
      • Crust Network: IPFS pinning paid from a renewal pool that orders can be topped up.
      • Bitcoin SV: data in transactions; miners are not paid to keep old data and may prune it.
      • Internet Archive: free, not a blockchain; one organization keeps it.
      • Your own copies: several places you control, such as optical discs, checked from time to time.

          How the data is picked

          With a live block, each browser gets its own randomly picked partition (kept between visits), and each fetch starts at a random position in it, so tabs sharing a key rarely hold the same data. A live block fetches chunks at one position in successive 3.5 GB sectors of your partition: they share their 32 packing entropies, so 1 or 1,024 of them cost the same packing time. Packed chunks are kept in this browser for this address.

          About export and import

          Export saves this address's packed chunks to a file; import loads such a file in another browser or a copy opened from disk, with no packing again. Chunks saved for other addresses are repacked for this one when mining starts, so all storage counts.

            Where the defaults come from

            The defaults are VirdPool's (ar.virdpool.com): 4% fee, 0.5 AR threshold, PPLNS. This assumes the pool's members together answer every range-2 lookup; a tab alone, trying one-chunk solutions only, waits about 100 times longer.

                Sign and send, or store free?

                Sign and send: a normal Arweave transaction straight to a gateway, paid in AR from your key, no bundler involved, up to 256 KiB. Store free: signed by your key as an ANS-104 item and handed to ArDrive's Turbo bundler, which stores up to 100 KiB without payment, so a key with no AR works; getting it into a block then depends on Turbo.

                  What is real here

                  Tested against mainnet
                  • Following the chain: all 317,041 accounts, then each new block's transactions and reward, match every block's account root.
                  • A real block rebuilt here from nothing but its solution comes out with the same block id.
                  • VDF steps and seeds, difficulty retargets and price adjustments match recent mainnet blocks.
                  • Replaying block 2,040,257 with real RandomX finds its own solution again: the same nonce and hash.
                  • Packing that block's unpacked chunks reproduces its packed sub-chunks exactly.
                  • The VDF recomputes step 119,924,183 to the block's output.
                  • Transactions match arweave-js, which verifies transactions signed here.
                  Not yet seen on mainnet
                  • Blocks built here were taken by an Arweave test network (a localnet), 37 in a row; none has reached mainnet yet, because that needs a real solution.
                  • If the 512 MiB RandomX cache cannot be allocated, the page falls back to SHA-256 stand-ins and says so.
